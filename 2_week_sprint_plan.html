2-week sprint plan for 2-person team building a Telebirr marketplace app

D1
Dev 1 · Backend
Express · Prisma · PostgreSQL
D2
Dev 2 · Frontend
Telebirr Mini-App · SDK · UI
WEEK 1
Project setup
Express app, folder structure from GEMINI.md, Prisma + Postgres config, .env, base error handler
Days 1–2
Prisma schema + Auth API
All 4 models + initial migration. POST /auth/register, POST /auth/login, JWT middleware
Days 3–4
Listings CRUD API
5 endpoints: create, list (search + filter by subject/exam type), get by id, update, soft delete
Day 5
Mini-app setup
Telebirr SDK init, routing/navigation, API client (base URL + auth header), design tokens
Days 1–2
Auth screens
Login, register + role picker (Sharer / Taker / Both), token storage, post-login redirect
Days 3–4
Home + Discovery
Listings feed, search + filter bar, listing card component — use mock data until API is ready
Day 5
End of Week 1 sync — Auth + Listings API is live. Dev 2 swaps mock data for real API calls. Both test together.
WEEK 2
Transaction API
Initiate, get status, confirm endpoints. Platform cut calculation service (cut % from .env)
Days 1–2
Telebirr payment integration
POST /payments/initiate, POST /payments/callback (webhook handler), sync status to transactions
Days 3–4
Reviews + bug fixes
POST /reviews, GET /users/:id/reviews, update user rating_avg. Fix bugs from integration testing
Day 5
Listing detail + Create listing
Taker's listing detail view. Sharer's create listing form (subject, exam type, price, description)
Day 1
Transaction + Payment flow UI
Book/initiate CTA, Telebirr native payment trigger, payment pending / success / error screens
Days 2–3
Profile + Polish
Sharer earnings screen, Taker order history, leave-a-review form, final UI polish
Days 4–5
End of Week 2 — Full end-to-end test together. Run the full flow: create listing → pay → confirm → leave review.
